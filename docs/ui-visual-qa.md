# UI visual QA

A record of the visual review of both web UIs on **2026-10-27**: every implemented route, the states captured, the screenshots, and the defects found. Screenshots are in [images/](images/), captured from the running applications in headless Chrome 156 over the Chrome DevTools protocol, with a script kept outside the repository.

## How the screenshots were made

- **Stack:** the existing local Compose stack (started earlier with `compose.yaml` and `compose.faults.yaml`; orders API, worker, Postgres, Jaeger, Prometheus, collector), left running and not restarted.
- **Applications:** the dashboard served by `pnpm web` (port 3100, current build) and the storefront's production build served by `pnpm commerce:preview` (port 4174). Two extra dashboard instances on other ports were used for states the real stack cannot show truthfully: an **empty incidents directory**, and **upstream URLs pointing at unused ports** (every component "unreachable").
- **Data:** real local data from earlier runs: eight incident bundles (five scenarios) and the orders already in the database. **No order was placed and no scenario, fault or load run was started** for this review. The one write-adjacent interaction was submitting an unknown SKU, which the API rejected with 422 and which created no order.
- **Viewports:** desktop 1440 × 900 (full page where longer) and mobile 390 × 844 at device scale 2.
- **Checked per page:** document title, console errors, failed or 4xx/5xx requests, broken images, horizontal overflow.
- **Privacy:** the images show order ids, SKUs and incident data from a local synthetic workload. No credentials, tokens or personal data appear; the `commerce` / `commerce` Postgres development password is not displayed anywhere.

## Defects found and fixed

1. **Dashboard chart: overlapping labels and a clipped axis label.** When the fault start and the detection are seconds apart, the "fault start" and "detected" labels were printed on top of each other, and the largest value's label was cut off at the left edge. The chart now puts the detection label on a second row and reserves room on the left. Test: [`apps/web/client/test/symptom-chart.test.tsx`](../apps/web/client/test/symptom-chart.test.tsx).
2. **Storefront `/favicon.ico` returned 404.** The page now links `public/favicon.svg`. Test: [`apps/commerce-web/test/static-assets.test.ts`](../apps/commerce-web/test/static-assets.test.ts).

The tests check the generated markup and the page source; the visual result was verified in the browser.

## Not fixed, by choice

- The dashboard answers `/favicon.ico` with its HTML page and status 200 (the single-page fallback). Browsers ignore it, so nothing breaks.
- Several incident-detail captures show a long traces list beside an almost empty logs panel; the layout is intentional (a log summary, not a log viewer).
